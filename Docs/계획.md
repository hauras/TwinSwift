# TwinSwift 계획

작성 2026-10-13. 1차(SProject) 세션에서 정한 내용.

## 1. 목표
- 취업용 포트폴리오 (언리얼 클라이언트 프로그래머)
- 4~5주 안에 완성하고 지원 시작
- 이야기: "1차를 측정해 한계를 찾고 → 2차에서 구조부터 재설계 → 숫자로 개선 확인"

## 2. 컨셉
**두 캐릭터(전사·마법사)를 실시간으로 바꿔 가며 싸우는 3D 태그 액션 보스 러시**

| 항목 | 결정 |
|---|---|
| 구조 | 보스 러시: 보스 3마리, 보스 사이에 강화 선택 |
| 핵심 | 태그. 모든 보스가 교체를 잘해야 이기게 |
| 시점 | **쿼터뷰로 진행** (2026-10-14). 3인칭은 V키로 남겨 둠. 스킬 겨냥 방식이 정해지는 단계 7 전에 최종 확정 |
| 체력 | **캐릭터마다 따로** (2026-10-15). 대기 중인 캐릭터는 천천히 회복, 한 명이 쓰러지면 남은 캐릭터로 계속, 둘 다 쓰러지면 끝 |
| 배경 | **미정** |
| 부위 파괴 | **미정**: 넣으면 3인칭+락온, 보스 수 축소 |
| 캐릭터 에셋 | 저폴리 Knight(팔레트 텍스처 512 한 장) + 대검. 마법사는 같은 스타일로 찾는 중 |

### 태그 규칙
- **스킬 입력 = 교체**: 상대 캐릭터 스킬을 누르면 교체하며 바로 시전 (메이플 제로 방식)
- **교체 어시스트**: 나가는 캐릭터가 한 방 남김
- **타이밍 교체**: 맞기 직전 교체하면 회피 + 짧은 슬로 모션
- **확정 표식 (양방향)**: 확률이 아니라 특정 스킬이 표식을 걸고, 상대 캐릭터가 터뜨림
  - 전사 [균열] → 마법사 낙뢰가 연쇄 폭발
  - 마법사 [빙결] → 전사 스킬이 산산조각

### 스킬 구성 (새로 짬. 1차 스킬은 가져오지 않고 틀만 가져옴)
| | 전사 (근접, 대검) | 마법사 (원거리, 커서 겨냥) |
|---|---|---|
| 기본 공격 | 좌클릭 2타 콤보 (배율 1.0 / 1.6) | 화염탄: 작고 빠른 단일 타격 연사 (화상·폭발 범위 없음, 냉기탄과 색으로 구분) |
| 스킬 1 | Q 돌진 베기: 커서 방향 6m, 경로 타격 (1.8, 쿨 6초) | E 냉기탄: [빙결] |
| 스킬 2 | W 내려찍기: 커서 위치 착지, 반경 3m, [균열] (2.2, 쿨 10초) | R 낙뢰: 커서 위치 범위, [균열] 터뜨림 |
| 교체 어시스트 | 회전 베기 (1.2) | 냉기 장판 |
| 회피 | Space 구르기 (0.3초 무적) | 짧은 순간이동 |
| 패시브 | 산산조각: [빙결] 적을 치면 3.0 + 경직 | |

- 스킬은 캐릭터당 2개로 시작 (스킬 입력 = 교체라서 Q·W / E·R 4키). 시간이 남으면 궁극기
- 전사 콤보 애니: 1타 `A_Knight_Slash_03`(대각선 내려치기), 2타 `A_Knight_Slash_01`(가로 베기, 마무리). `A_Knight_Slash_02`는 1.8초 중 1.4초가 머리 위 칼 돌리기라 뺌

### 보스 3마리 = 태그 교육 과정
| 보스 | 시험하는 것 |
|---|---|
| 1 | 시너지 (표식 → 교체 → 폭발) |
| 2 | 타이밍 교체 (연속 공격을 교체로 회피·반격) |
| 3 | 교체 패턴 읽기 (플레이어의 교체 습관을 학습해 노림) |

## 3. 기술 방침
- 엔진 UE 5.7. 하드웨어 레이트레이싱·Substrate·가상 그림자맵 끔, Scalable 시작. Lumen은 측정 후 결정
- 에셋: 저폴리 Knight + 대검 애니(뼈 이름이 기사와 같아 리타깃 없이 기사 스켈레톤에 임포트, `Tools/import_knight_anims.py`). Paragon 사용 안 함
- 태그 구조: **캐릭터 하나에 몸(메시) 둘 = 상주형**. 교체를 GAS 능력으로 만들어 클라 예측 실행. Possess·InitAbilityActorInfo 반복 없음
- 네트워크: **지금은 순수 싱글로 작성** (2026-10-14 결정). 멀티는 나중에 추가 (아래 "멀티 추가 시 할 일")
- 조준: `GetAimPoint()`로 분리 → 시점을 바꿔도 스킬 코드 그대로
- 카메라 설정은 데이터 에셋 하나로
- 애니메이션 연결: `OnBlendOut` 종료, 입력 버퍼, 캔슬 윈도우, 서 있으면 전신·움직이면 상체
- 애님 로직은 C++ AnimInstance에서 계산, 그래프는 연결만
- 데미지: SetByCaller 계수 (스킬마다 배율)
- 자료구조 (포트폴리오, 전후 숫자로 기록):
  - 투사체·데미지 숫자 **오브젝트 풀** (빈 칸 스택, 꺼내기·반납 O(1)) → Insights로 생성 비용·GC 멈춤 비교 (단계 7-B)
  - 균열 **연쇄 폭발 = BFS** (방문 표시 `TSet`, 깊이 제한, 단계별 시간차). 대상이 많으면 **공간 해시 격자**로 주변 칸만 검사 → O(n²)와 시간 비교 (단계 8)
  - 시간이 남으면: 보스 패턴 셔플 백·예약 이벤트 최소 힙 (보스), 입력 원형 버퍼 (손맛)

### 단계 10-3a: 탄막 패턴 데이터화 (2026-10-26)

- 판단:
  - 교체 쿨다운 2초 → 색을 0.6초마다 바꾸는 벽은 못 깸. 색이 바뀌는 간격 ≥ 2초, 같은 색이 연달아 오는 구간은 짧게
  - 협공 벽의 "섞인 색" 차례: 한 캐릭터로 다 못 막음 → 1페이즈에서 배운 색 판단 위에 무적 타이밍을 요구 (차례 간격 1.2초 > 회피 쿨다운 1초라 회피만으로도 깰 수 있음)
  - 하강을 루트 모션 이동 대신 높이만 직접 보간: 루트 모션은 시작·끝만 정하고 경로는 이동 컴포넌트가 계산 → 비스듬해짐. 감속 곡선(1 - (1-t)³)은 출발 속도가 평균의 3배라 "툭 떨어짐" → SmoothStep(최대 1.5배)
  - 등장 몽타주를 충격파와 같게: 등장에서 본 동작·색이 그대로 근접 패턴의 예고가 됨
- 확인: PIE에서 등장 하강·색 소개·첫 박, 2페이즈 50% 진입 로그 + 안내 글자, 협공 벽, 크기 2배
- 문제 → 원인 → 해결:
  - "벽이 안 나옴" → 2페이즈(13초 만에 진입)에서는 한 방향 벽을 일부러 뺐는데 협공 벽이 아직 없었음 → 협공 벽 추가, 패턴 발동 로그로 다음엔 바로 구분
  - (리뷰) 패턴 시뮬레이션의 무작위 비교군에 다른 페이즈 패턴이 섞임 → 페이즈 조건을 실제 고르기에만 넣었음 → `IsInCurrentPhase` 하나로 모아 두 곳이 같이 씀, 측정 거리 범위도 지금 페이즈 패턴만
  - (리뷰) 어시스트 잔상 검에서 나나이트 경고 반복 → 반투명 재질은 나나이트로 못 그림 → 잔상 액터의 검 컴포넌트만 `bDisallowNanite` (검 에셋은 그대로)
- 남은 것: 조명 격자 한도 초과 경고 원인 조사(이펙트 라이트 렌더러 의심), 탄이 커진 몸 안에서 생겨 보이면 `MuzzleOffset` 100 → 150, 이름 자막이 하강 중에 뜸(HUD 공용 값 1.8초)

### 보스 3 방향 결정 (2026-10-27)
- 후보였던 "습관 학습 보스"(상황별 반응 빈도 + 밴딧): 체감이 약함(숨은 확률표), 반응 종류가 적어(교체/회피/그대로) 무작위 33%와 차이가 작음, 새 보스 에셋 필요, 클라이언트 직무와 거리 → 보류
- 정한 것: **거울 보스** = 내 전사·마법사와 같은 모델(검은 유리 재질 + 가장자리 빛, 1.2~1.3배, 눈·무기 보라)이 내 행동(이동·공격·스킬·교체·회피)을 원형 버퍼로 기록해 3초 뒤 재생. 2페이즈 지연 1.5초 + 가끔 거꾸로 재생
  - 주제 "교체 습관 읽기"를 눈에 보이게: 내 콤보가 3초 뒤 나한테 돌아옴
  - 기술: 행동 기록 원형 버퍼, 기록 → 재생(리플레이·고스트와 같은 기술), 결정적 재생 검증. 숫자: 기록 크기, 재생 오차, 비용
  - 에셋 재사용(메시·애니·능력). 큰 작업은 플레이어 능력을 AI가 쓰게 조준·입력 방향을 푸는 것
- 순서: 탄막 측정 마무리 → 런 진행(보스 1 → 강화 → 보스 2) → 멀티 검증(Listen Server 2인, `Net PktLag=500`) → README·영상 → 보스 3
- 반투명 재질을 쓰지 않는 이유: 겹침 순서 꼬임·그리기 비용·나나이트 제약, 무엇보다 동작이 잘 안 보임 (동작을 읽는 보스)

### 단계 10-4 계획: 런 진행 (2026-10-27)
- 정한 것: 한 경기장에서 보스가 차례로 등장 (맵을 나누면 강화·체력을 넘기는 저장 장치, 멀티면 이동 동기화까지 필요). 레벨에 보스를 놓지 않음 → 런 진행 액터가 클래스 목록으로 차례마다 생성, 한 번에 보스 하나. 강화는 6개 중 무작위 3장(카드, 화면 가운데, 게임 정지), 고르면 잃은 체력 50% 회복 + 쓰러진 캐릭터 30%로 부활. 단조로움은 보스마다 조명·안개 색으로
- 순서: ① 전투 진행 액터가 보스를 받아서 씀(`StartWithBoss`, 보스 바뀜 알림, HUD 다시 묶기, 레벨 지정 칸 제거) → ② 런 진행(생성 → 전투 → 다음 보스, 시작 순서 칸) → ③ 강화 데이터 + 카드 화면 → ④ 런 클리어 화면 + 보스별 조명
- 런 진행 자리: 새 액터 대신 기존 `ASGameMode` → 게임 규칙의 정해진 자리, 레벨에 놓을 것 없음, 멀티에서 서버에만 있어 보스 생성도 서버만. 역할: 게임 모드 = 순서 / 전투 진행 액터 = 한 판 보여 주기 / 보스 = 싸움

### 단계 10-4 ①②: 보스를 생성해 차례로 (2026-10-27)
- 한 것:
  - `ASBossEncounter`: 레벨 보스 칸 제거 → `StartWithBoss(보스, 마지막인지)`(이전 보스 알림 해제 → 새 보스 → 등장부터), 플레이어 진입은 `OnPlayerEntered`로 알리기만, 보스 바뀜 `OnBossChanged`, 중간 처치 상태 `Cleared`(결과 화면 없이 대기), 생성 자리 `GetBossSpawnTransform`(플레이어 반대쪽 가장자리 12m에서 플레이어를 봄), 플레이어 패배 구독은 한 번만
  - `USBossHUDWidget`: 보스 묶기를 `BindBoss`/`UnbindBoss`로 분리 → 보스 바뀔 때 다시 묶음, 중간 처치 "바위 골렘 처치 N초"
  - `ASGameMode`(직접 작성): `BossCharacterClasses`·`StartIndex`·`NextBossDelay`, 진입 → 첫 보스 생성, `Cleared` → 3초 뒤 쓰러진 보스 삭제 → 다음 보스. 생성 겹침은 `AdjustIfPossibleButAlwaysSpawn`
  - `BP_GameMode` 보스 순서 골렘 → 지휘자, `L_Dev`의 지휘자 삭제 (`Tools/setup_run.py`)
- 확인: PIE에서 골렘 등장·처치 → "처치" → 지휘자 등장(체력바 이름 바뀜) → 클리어 화면
- 문제 → 원인 → 해결: (리뷰) 모든 보스가 마지막으로 판정될 뻔함 → `const bool bLastBoss = Num() - 1`처럼 숫자를 bool에 넣으면 0이 아니면 참 → `Index == Num() - 1`로 비교

## 9. 멀티 추가 시 할 일 (단계 3에서 싱글로 바꾸며 뺀 것)
- `USGameplayAbility`: NetExecutionPolicy `LocalOnly` → `LocalPredicted`
- `ASPlayerState`: ASC `SetIsReplicated(true)`, `SetReplicationMode(Mixed)`, `SetNetUpdateFrequency(100)`
- `AEnemyCharacter`: ASC `SetIsReplicated(true)`, `SetReplicationMode(Minimal)`
- `USAttributeSet`: Health·MaxHealth·AttackPower `ReplicatedUsing` + `OnRep_*`(GAMEPLAYATTRIBUTE_REPNOTIFY) + `GetLifetimeReplicatedProps`
- `APlayerCharacter`: 클라 GAS 초기화 `OnRep_PlayerState`, 시작 능력·스탯 지급에 `HasAuthority()`, 걷기 `Server_SetWalking` RPC, 메시 `VisibilityBasedAnimTickOption = AlwaysTickPoseAndRefreshBones`(서버 칼날 판정용)
- `USAbilitySystemComponent::AddStartupAbilities`: `IsOwnerActorAuthoritative()` 체크
- `UGA_AttackBase`: 데미지 적용 전 `HasAuthority(&CurrentActivationInfo)`, `FaceAimPoint`는 `IsLocallyControlled()`일 때만
- `UANS_WeaponTrace`: 판정을 `Owner->HasAuthority()`일 때만
- 데미지 숫자: `ShowDamageNumber` → `UFUNCTION(Client, Unreliable) Client_ShowDamageNumber` (화면 흔들림 `ClientStartCameraShake`는 이미 클라 RPC)
- 히트스톱: `CustomTimeDilation`은 복제 안 됨 → 서버에서 Multicast(Unreliable)로 각 화면에 알림
- 균열 연쇄·산산조각: 판정은 서버에서만 (`ApplyDamageTo` 경로가 권한 체크를 지나는지 확인)
- 태그 교체 (단계 5): 교체(`SwapTo`)를 GAS 능력 또는 Server RPC로, `ActiveSlot` 복제(`ReplicatedUsing`), 교체 바닥 이펙트(`PlaySwapEffect`)는 GameplayCue로 옮겨 다른 화면에도 보이게
- 확인: Listen Server 2인 + `Net PktLag=500`
